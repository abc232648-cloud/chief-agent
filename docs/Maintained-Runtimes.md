# Runtime selection and maintenance

Windows tests use CPython 3.12.14 with private SQLite 3.53.4. The Ubuntu 26.04 VM uses distribution CPython 3.14.4 with private SQLite 3.53.4. Different interpreter builds require separate results. Python lists 3.12 in security maintenance and 3.14 in bug-fix maintenance. [Python lifecycle](https://devguide.python.org/versions/)

The selected browser is Chrome 154.0.8037.57: Chrome for Testing on Windows and the standard Google Chrome stable package on Ubuntu. Exact executable and archive hashes are in the platform inventories. Ubuntu's root-owned installation supplies standard OS sandbox integration. The developer-location build could not start sandboxed under this VM's AppArmor restrictions; installing the standard package resolved the focused browser checks without disabling security controls. [Chromium sandbox documentation](https://chromium.googlesource.com/chromium/src/+/main/docs/security/apparmor-userns-restrictions.md)

`CHIEF_BROWSER_RUNTIME`, or service field `browser_runtime`, references a bounded non-secret JSON object with exactly `executable`, `sha256`, and `version`. Paths must be absolute and plain. Explicit launches verify the executable digest and request `chromium_sandbox=True`. Mismatch or sandbox failure does not trigger a fallback. Production browsing requires explicit selection. The version is descriptive metadata; the digest verifies executable identity, not a signature or every browser resource. Installation ownership and full-package provenance also matter.

SQLite came from official 3.53.4 Windows DLL and source-amalgamation distributions with published SHA3-256 verification. Windows uses a private interpreter copy. Ubuntu uses a private library selected explicitly at launch, with compiler/build receipts recorded separately. Neither replaces shared system libraries. Services must use the same library selection as their tests: a virtual environment alone does not select SQLite. [SQLite downloads](https://www.sqlite.org/download.html)

An older distribution version number does not prove missing patches; distributors can backport fixes. Record provenance and version. Private runtimes still require maintenance. Review security updates, install in isolation, rerun relevant regressions and full acceptance, then repin the identity. Do not preserve obsolete browsers just to retain a digest, disable updates without another maintenance process, or silently repin changed executables. Runtime binaries, profiles, cookies and credentials are excluded from source archives.
